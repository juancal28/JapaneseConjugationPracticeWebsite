# Japanese Conjugation Practice with your own Anki decks

A recreation of [steven-kraft.com's Random Verb Conjugation Practice](https://steven-kraft.com/projects/japanese/randomize/)
(same look, same quiz behavior) that can also drill **only the words from your own Anki decks**, such as one textbook
chapter or one Duolingo unit. Verbs and い/な-adjectives are practiced; nouns and phrases are skipped.

## Setup

Requires Node 22.15+ (for built-in zstd, used by modern Anki exports).

```sh
npm install
npm run setup:jmdict          # downloads JMdict (~12 MB) and builds data/jmdict/index.json (gitignored)
cp .env.example .env          # then put your Anthropic API key in ANTHROPIC_API_KEY
npm run dev                   # http://localhost:5173
```

Run `npm run setup:jmdict` once on each computer. Without it, imports still work, but word types are guessed only by
Claude (or not at all).

## Practicing

- `/` is the practice page. Type romaji, which turns into kana as you type, then press **Enter** to submit and
  **Enter** again for the next word. **Shift** toggles furigana when Show Kanji is on.
- The **Decks** box under Settings picks which decks to draw words from. You can select several; with none selected, the built-in verbs are used.
- When the selected decks include adjectives, an extra row of "Adj." form toggles appears.
- `/reference` lists every answer the quiz accepts with the rule that builds it, using one table per word type and
  one row per quiz form, plus an exceptions table. The rules live in `client/src/reference/referenceData.ts` and the
  examples are generated by the engine. `test/reference.test.ts` fails if any accepted answer has no rule.

## Importing an Anki deck

1. In Anki: **File → Export → Anki Deck Package (.apkg)**. Both "support older Anki versions" and current
   exports work. Audio and images are ignored.
2. Open `/decks` (the **‹** on the practice page) and drop the file in.
3. Tick the subdeck(s) you want, e.g. just "Lesson 3", and check which card fields hold the Japanese word, its
   reading and the English meaning. These are pre-filled by guessing; Anki furigana like `食[た]べる` is understood.
4. **Classify** runs each card through:
   - **JMdict**: dictionary part of speech, e.g. godan vs ichidan, い vs な, する-verbs, and the 行く/ある/くださる/いい exceptions.
   - **Claude** (`claude-opus-5-5`): reviews every card. It fixes conjugated or messy cards (食べます → 食べる),
     resolves ambiguous ones, skips nouns and phrases, and leaves a note when it disagrees with JMdict. Requests use
     the API's server-side refusal fallback (`fallbacks: "default"`).
5. **Review** the table. Rows needing attention are highlighted, and every row shows a live preview of a few
   conjugations so mistakes stand out. Fix anything, then **Save deck**.

Saved decks can be edited or deleted later from `/decks`.

## Decks live in git

Every deck is two files in the repo:

```
decks/<deck-slug>/words.json        the reviewed word list (kana, kanji with ruby, English, type, exception)
decks/<deck-slug>/answer-key.json   every form × every option combination, generated from words.json
```

After importing or editing, commit `decks/<slug>/`. On another computer, `git pull` and the deck shows up.
The answer key is generated by the conjugation engine, not by AI. If the engine ever changes, regenerate all keys
with `npm run keys:rebuild`.

## Scripts

| Command | What it does |
|---|---|
| `npm run dev` | Express API (:3001) + Vite dev server (:5173) |
| `npm test` | Engine golden tests, parser, JMdict, pipeline, and validation tests |
| `npm run build && npm start` | Production build; Express serves `dist/` and the API on `$PORT` |
| `npm run setup:jmdict` | Download and index JMdict (pinned release) |
| `npm run keys:rebuild` | Regenerate every deck's `answer-key.json` |
| `npm run builtin:build` | Rebuild the built-in decks from the original site's word lists |
| `npm run fixture:reference` | Regenerate `test/fixtures/reference-answers.json` from the original site's code |

## How correctness is checked

`test/engine.test.ts` compares this engine's kana answers to the **original site's own conjugation code** for all
212 built-in words × every form × every option combination (fixture generated by `npm run fixture:reference`).
The engine also generalizes the original's hard-coded irregulars, so any する/来る compound works, and adds
くださる-type verbs, くれる, and いい-compounds (かっこいい). Intentional deviations:

- ある: the negative conditional/provisional are なかったら/なければ (the original gives あらなかったら/あらなければ).
- The polite imperative also accepts the request forms 〜てください (書いてください) and 〜ないでください (書かないでください), alongside the original's 〜なさい / 〜なさるな.
- い-adjective polite negative also accepts 〜くないです (高くないです) alongside 〜くありません.
- Honorific verbs (くださる, いらっしゃる…) use 〜いませ for the polite imperative (くださいませ), and くれる's polite imperative is no longer a negative.
- Kanji display fixes: the original's 来る and 勉強する kanji imperatives were broken, and 来る's kanji ruby is now correct everywhere.
- The original could freeze when only one unanswered word was left; that's fixed.
- The original's feedback button (a link to its author's Google Form) is not included.

## Deploying later (Railway)

`npm run build && npm start` is all Railway needs (set `PORT` and `ANTHROPIC_API_KEY`). One caveat: Railway's
filesystem is ephemeral, so decks uploaded on the hosted site would be lost on redeploy and wouldn't reach git.
Decks committed to the repo are served fine. To import on the hosted site, add another `DeckStore` implementation
(`server/store/deckStore.ts`), e.g. a Railway volume or one that commits through the GitHub API.
